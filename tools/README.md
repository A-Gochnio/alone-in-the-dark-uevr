# Live diagnostics and revolver trial

These PowerShell tools use the locally installed uevr-mcp v1.0.0 HTTP bridge. Start the Steam game, inject UEVR with OpenXR, and load a save first. Port defaults to 8899. They check game identity and discover current addresses; no addresses should be copied across loads.

* `./tools/Invoke-AitDUevrInject.ps1` replaces the UEVR frontend's Inject button. It waits for the game window and its D3D renderer, then LoadLibraryW-injects `openxr_loader.dll` (or `openvr_api.dll` with `-Runtime OpenVR`), `UEVRPluginNullifier.dll` and `UEVRBackend.dll` from the rai-pal uevr-nightly folder. It waits for `/api/game_info` and sends Insert to close the UEVR overlay (`-KeepOverlay` skips that). Verified 2026-10-23 on a direct `-dx12` launch. With `-NoBridge`, or automatically when `uevr_mcp.dll` is not in the profile's `plugins/` folder (the normal state for play and benchmarks, because the plugin caps the game at ~42 FPS), it confirms injection from UEVR's `log.txt` swapchain creation and posts Insert to the window. Verified 2026-10-24.
* `./tools/Build-AitDRelease.ps1` builds the player release (Discord) from the last commit: `dist/AloneInTheDark-VR-v<version>.zip` with the UEVR profile zip for UEVRInjector's Import Config, `README.txt` and `Engine-ini-additions.txt`. Rerun it after any mod change; `-Version 0.2.0` bumps `release/VERSION`. It packages only `config.txt`, `cvars_data.txt`, `uobjecthook/*.json`, `alone_in_the_dark_vr.lua` and `aitd_vr*.lua`, rejects dev-only content, and stops if the live UEVR settings (`config.txt`, `uobjecthook/`) on this PC differ from the committed `profile/` (copy the changes into `profile/` and commit first, or pass `-IgnoreLiveDiff`). See `release/RELEASING.md`.
* `./tools/Get-AitDWindowShot.ps1 -Keys Escape -Out local/ui-captures/pause.png` posts keys to the game window (no focus needed; `sleepNNN` inserts a pause) and captures the window, which includes the game UI. Works without the bridge.
* `./tools/Measure-AitDPerf.ps1` takes engine frame times from the CSV profiler through the bridge, or with `-NoBridge` from the tick log written by `profile/scripts/aitd_perf_log.lua`, plus process 3D busy time, NVENC FPS and stream bandwidth.
* `./tools/Set-AitDVRGraphics.ps1 -Override @{…} -SystemSettings @{…}` writes menu keys to both `GameUserSettings.ini` and `settings.sav`, and CVars to the `[SystemSettings]` section of `Engine.ini`, with backups that `-Mode Restore` reverts.
* `./tools/Capture-AimSnapshot.ps1 -Label baseline` records read-only getters under ignored `local/aim-captures/`. Successfully exercised on Edward in Derceto. Sequential samples are not synchronized to a shot; they cannot establish hit detection by themselves.
* `./tools/Set-RevolverAttachment.ps1` applies the experimental right-hand root attachment. The archived offset made the barrel point right and `Left90Pre` made it point back at the player. The default `Right90Pre` is the opposite correction and is the current forward-facing candidate. Use `-Rotation Archived` or `-Rotation Left90Pre` to reproduce those earlier results.
* `./tools/Set-RevolverAttachment.ps1 -Detach` removes that trial from the currently selected revolver. Reload the save if an animation does not restore its normal pose. Restart clears runtime attachment state; these tools do not write UEVR profile settings.

`profile/scripts/alone_in_the_dark_vr.lua` swaps the XInput LT and RB inputs exposed by UEVR. With the game's stock bindings this gives right grip to aim, right trigger to fire, and left trigger to melee. Copy it to the active UEVR profile's `scripts/` folder; it loads on the next injection or Lua script reset. Do not combine it with an in-game/custom mapping that already swaps Aim and Melee, because that would swap the inputs twice.

The archived offset's original author is unverified. The API's `permanent` flag applies the controller transform to gameplay; it is not a promise of saved configuration or level-transition handling. Live sampling shows the game's trace follows the camera center ray even while the weapon root follows the controller, so this trial remains visual only. It does not implement weapon switching, holster handling, flashlight attachment, or a bullet-origin override. Do not install it as an automatic startup script yet.

Validation sequence: capture baseline, draw the revolver, apply attachment, verify grip/barrel alignment in headset, hold head still while rotating the right hand, translate the hand sideways while keeping its orientation fixed, compare getter snapshots, then shoot a visible target and inspect actual hit locations/occlusion. Preserve normal reload/menu/interaction controls. A successful firing input alone does not establish correct tracked aiming.

## Simulated Quest input and puzzle tests (2026-10-26)

* `tools/test/aitd_test_sim.lua` (copy into the UEVR profile's `scripts/` for a test session only) replaces the XInput state inside UEVR's hook with commands from `data/aitd_sim_input.txt`. It loads before `alone_in_the_dark_vr.lua` (alphabetical), so its callback runs first and the remap sees the simulated state, exactly where UEVR reports the Quest controllers. It also writes `data/aitd_sim_ack.txt` and `data/aitd_sim_probe.txt` (XInput call counts per pad index).
* `./tools/Send-AitDSimQuest.ps1 -Press RightGrip,A -LeftStick x,y -RightStick x,y -Seconds 0.3` writes those commands with Quest names (RightGrip = RB, LeftGrip = LB, triggers, A/B/X/Y, L3/R3, Menu).
* The hook only fires while the game polls a connected pad. With the headset off the desk, Virtual Desktop stops tracking the controllers and UEVR offers no pad, so run `./tools/Start-AitDVirtualPad.ps1` (ViGEmBus virtual Xbox 360 pad, needs the ViGEmBus driver). Keep it neutral: the game also reads a physical pad through a path that bypasses UEVR's hook, so buttons sent on the virtual pad itself would reach the game unremapped (left trigger aimed directly). The pad server reads `data/aitd_pad_input.txt`, which the sender does not write.
* `./tools/Restore-AitDSaves.ps1 [-RestoreSettings]` restores the saves (and with the switch the settings and volume) from the latest `backups/saves-before-puzzle-tests-*` backup and verifies hashes.
* Loading sections: `GameSubsystem_ChapterSelect.OpenLevel(DA_CS_Chapter<N>_<Edw|Emi>)` (call from the main menu, where the data assets are loaded) starts any chapter. In that fresh state the game crashes (null read, `AloneInTheDark+0x18706b7`) when the investigation menu, a document or a pick-up card opens; force an autosave (`PiecesSaveSubsystem.DelayedAutoSave`), return to the main menu and Continue, after which everything works. `InventoryBlueprintLibrary.AddItemToInventory` gives key items. Entering a puzzle with `PuzzleActor.EnterPuzzle` shows it but its input is not hooked up; walk to it and press A instead.

## Public repository export

* `./tools/Export-AitDPublic.ps1 -PublicClone <path to a clone of the public repo>` copies this repo's last commit into the public clone and commits it there. Paths marked `export-ignore` in `.gitattributes` (agent notes, `local/`) are left out, the copy is checked for personal paths and names, and the public clone must commit with a GitHub noreply email. Push the public clone yourself after reviewing.
* Machine-specific settings (game folder override, game window position) go in the ignored `local/machine.psd1`; see the repository README. `tools/AitDCommon.ps1` reads it and otherwise finds the game through Steam.
